## 1. Purpose and Scope

This policy inventories every third-party service and external CI/CD dependency that this system actually sends data to, grants access to, or otherwise depends on, and states what data or access each one has. It satisfies SOC 2 CC9.2 (vendor management) and ISO/IEC 27001:2022 A.5.19–A.5.22 (supplier relationships). The inventory below is built from this repository's actual, current dependencies — not a generic vendor-management template — and should be updated whenever a new external service is added to the CI/CD pipeline, the Terraform configuration, or the application code.

## 3. Selection and Onboarding Criteria for a New Vendor

Before adding a new external service that will receive data from, or gain write access to, this system:

1. Document what data or access it will receive, using the same level of specificity as Section 2's table (not "logs" — specify which logs, from which components, over what time window).
2. If the vendor will receive application data (as opposed to source code or CI metadata), confirm whether that data includes anything from [`DATA_CLASSIFICATION_RETENTION_POLICY.md`](DATA_CLASSIFICATION_RETENTION_POLICY.md)'s PII or "sensitive" classes, and flag it explicitly if so — as the Claude API entry above does.
3. Prefer commit-SHA pinning over floating version tags for any GitHub Action, matching the existing convention.
4. Add the new vendor to Section 2's table as part of the same pull request that introduces the dependency — this policy is meant to stay current with the codebase, not be reconciled after the fact.

## 4. Offboarding

When a vendor integration is removed (as CloudTrail/GuardDuty/CloudWatch were removed 2026-08-23 per [`../ARCHITECTURE.md`](../ARCHITECTURE.md), before being partially reinstated this session — see [`INFORMATION_SECURITY_POLICY.md`](INFORMATION_SECURITY_POLICY.md) Section 4.3), remove the corresponding row from Section 2's table in the same change that removes the dependency, and confirm any associated credential (API key, OIDC trust relationship, Secrets Manager entry) is deleted, not merely unused.
